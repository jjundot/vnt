# 带宽感知迁移（实验实现）

实现基于用户 fork：`jjundot/vnt`（基线 cff68aa）与 `jjundot/vnts`（基线 dbda8c5）。客户端、服务端须配套升级；旧版本保持普通转发，但不参与新的容量准入。默认关闭自动迁移。

## 配置

VNTS 的 `config.toml` 单独配置公网两个方向的购买额度，单位为十进制 Mbps：

```toml
[bandwidth]
enabled = true
automatic = false
inbound_mbps = 1000
outbound_mbps = 100
public_interfaces = ["eth0"]
safety_percent = 10
```

先运行观察模式；验证计量口径及建议后，服务端设置 `automatic = true`。客户端 TOML / Web 启动配置 / Android JNI JSON 使用：

```toml
bandwidth_mode = "observe" # off / observe / auto；默认 off
```

客户端 `auto` 且源、目标服务端均允许自动迁移时，才执行迁移。订阅高级配置支持下发该字段；改变模式会重建客户端实例。Android Java 示例提供 `setBandwidthMode()`。

Linux 读取所选公网接口的 sysfs RX/TX 累计字节；Windows 读取 PowerShell `Get-NetAdapterStatistics` 的 ReceivedBytes/SentBytes。私网互联须有独立可达路径。所选计量接口必须排除私网流量；公网私网共用网卡时，本版本没有按地址分类的采集器，不能直接用混合计数启用优化。接口不存在、计数回退或采样过期时，停止容量准入和优化，不停止业务转发。

服务端同时修复了 `persistence=false` 时，配置互联任务的停止句柄被丢弃、连接任务立即退出的问题，并补全了普通 VNT 客户端经服务端发现远端 VNT 节点的通告；IKEv2 / WireGuard 的可见性仍分别受原开关控制。

## 决策与稳定性

- 入站、出站独立采样和预留，包含接口上其他程序的用量；采样周期 1 秒，EWMA 系数 1/4，客户端每 5 秒请求状态。同一服务器的多个传输连接按服务器启动身份去重。
- 客户端分别学习持续上下行能力，完成多次持续传输后提高置信程度；短突发不计为有效传输，拥塞低速样本不下调历史能力。保留最近 8 次有效传输，用持续速率的上四分位估计能力，避免单次低速下调；30 分钟没有有效样本则降低为未知，网络采样中断时重新学习。当前需求与历史能力分开保存；学习状态暂存于当前运行实例，实例重建后重新学习。
- 试验默认：活跃速率至少 64 Kbps；持续活跃至少 15 秒；对应服务器方向利用率至少 85%，压力持续 30 秒；自动迁移还须有 RTT 比自身基线上升超过 15 ms 的证据；历史能力与当前吞吐的差距只辅助判断，观察模式可单独记录该差距的建议。只需某一方向受限，同时检查另一方向容量。
- 候选必须有有效统计、可达路由及足够余量；历史能力用于提供最多为当前持续速率两倍的增长预算，不直接将历史满带宽当作当前需求。新增预算另含 15% 开销裕量，准入余量严格大于预算的 1.5 倍；预计目标对应方向利用率至少改善 10 个百分点，客户端到服务器 RTT 增幅不得超过 50 ms。
- 当前未建立逐目的完整资源图，因此对可能新增的公网入站、出站均作保守预算。两个方向仍是独立账本；预算可能偏大，不承诺最优利用率。精确的增量归属及私网容量准入仍需后续完善。
- 客户端每次仅一个优化迁移，启动及成功迁移后驻留 300 秒。源服务器同一批仅允许一个迁出，目标服务器同一批仅允许一个迁入；90 秒等待负载及计量稳定。普通失败后退避 60 秒。
- 上传入口绑定覆盖普通中继单播，避免 RTT 或发送队列变化造成逐包切换；绑定不可达或服务器重启时恢复现有故障回退。P2P 优先级保持原有行为。
- 下载出口由接收客户端申请；获准提交后通过现有私网控制连接传播出口版本，入口服务器优先使用版本最高的可用出口。传播期间保留原转发能力。控制消息发送成功不等于所有入口已应用，尚无全网路由提交屏障。

这些时间及阈值是当前试验默认，集中在客户端控制器及服务端账本中；本轮没有为每个参数提供配置项。

## 准入与恢复

现有 RPC 增加兼容的 protobuf 字段，载荷是版本为 1 的 JSON。只允许已注册的客户端操作自身地址，迁移 ID、服务器启动身份、客户端实例身份和单调递增版本约束重复或迟到请求。

流程为：观察 → 源服务器批次许可 → 目标 FIFO 候补 → 原子预留 → 同一认证连接验证 → 提交 → 路由生效及计量交接。目标候补/批准有效期 30 秒，客户端候补窗口 25 秒；提交后临时容量占用保留最多 90 秒，与长期出口选择分离。取消不能撤销已提交操作；确认丢失时使用同一 ID 重试，下载出口也可通过已提交的版本恢复确认。

临时预留只扣除已由同一客户端、同一 EWMA 口径反映的新增用量，不能因接口总流量增加就释放。故障回退不等待普通容量候补或冷却。

## 构建和验证

```sh
# 客户端（CLI / Ctrl / Web）；先安装 Node.js + pnpm
pnpm install --frozen-lockfile
pnpm build:web
cargo build --locked --release -p vnt2 --features vnt-ipc,vnt-web --bins
cargo test --locked -p vnt-core -p vnt-ipc -p vnt-web -p vnt-jni -p vnt2 --features vnt-ipc,vnt-web --lib --bins

# 服务端；在 vnts 仓库执行
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend build
cargo test --locked --bin vnts2
cargo build --locked --release --bin vnts2
```

客户端部分既有网络测试需要 RAW socket 权限。在隔离的容器中运行，或在测试环境给测试进程相应权限。Android 使用仓库原有 NDK r27d / API 24、三个 ABI 及 16 KiB 对齐构建；JNI 库须由 Android 应用集成，不能将它当作 APK。Windows 提供 CLI / Ctrl / Web 可执行文件，TUN 驱动按原项目要求准备。

新增测试覆盖：分方向准入、并发请求及重复申请、EWMA 预留交接、超时/旧消息、迁出和迁入批次、客户端路径保持及故障/重启回退，以及通过真实 QUIC Datagram 验证出口版本覆盖 RTT。

## 验证边界

本轮的构建与自动测试不代替真实公网带宽环境的压测。上线前仍需测量长流迁移收益、控制消息分区、MTU 大包、乱序、Ping 丢包、TCP 停顿及混合版本行为。临时预算不提供长期硬带宽保证；私网瓶颈、CPU/PPS、完整路径 MTU 验证、精确跨节点资源增量、出口传播屏障及学习状态持久化尚未覆盖。
